## 二、PyTOD 预置配置（运行前定义）

### 2.1 场景上下文

```
这是一个外呼小额借款推介场景（安逸花外呼促活）。坐席代表安逸花/马上消费金融主动致电老用户，目标是激活用户闲置的借款额度。标准流程：① 核实用户身份（姓名/手机尾号）→ ② 告知可用额度和利率 → ③ 解答疑问（还款方式、账单争议等）→ ④ 引导用户在 APP 完成借款操作 → ⑤ 确认无未解决诉求后礼貌告别。注意：核实身份前不得告知账户详细信息；若用户有未解决诉求则不得直接告别。
```

### 2.2 ServiceSchema（服务意图与槽位定义）

服务名：AnYiHua_OutboundCall_Generation
描述：安逸花外呼促活服务 - 核实身份、告知额度、解答疑问、推动借款
意图数：9
槽位数：14

#### 意图列表

`verify_identity` — 开场身份核实：确认来电者是账户本人。调用 verify_customer API 传入用户提供的姓名和手机尾号，通过 identity_confirmed 字段确认身份后才可进行后续账户信息告知
- 必填槽位：`customer_name`、`identity_confirmed`
- 可选槽位：`phone_suffix`

`explain_credit_limit` — 告知额度情况。必须先调用 query_account API 获取 available_credit，不得自行计算或估算金额（防止数据错误）
- 必填槽位：`customer_name`、`available_credit`
- 可选槽位：`temp_credit`、`temp_credit_status`、`temp_expiry_days`

`explain_interest_rate` — 解释利率和还款方式，可调用 calculate_repayment API 获取具体数据
- 必填槽位：`customer_name`、`annual_rate_pct`
- 可选槽位：`term_months`

`calculate_repayment` — 计算指定金额和期数的月还款额。调用 calculate_repayment API，传入用户指定的 amount 和 months
- 必填槽位：`customer_name`
- 可选槽位：`inquiry_amount`、`term_months`

`explain_displayed_amount` — 解释 APP 显示金额的构成（用户质疑账户显示数字时使用）。调用 query_account 获取 available_credit 和 temp_credit，结合用户提到的 inquiry_amount 进行说明
- 必填槽位：`customer_name`、`inquiry_amount`
- 可选槽位：`available_credit`、`temp_credit`、`temp_credit_status`

`handle_loan_dispute` — 核实用户争议的借款记录，调用 query_loan_records API 获取事实数据
- 必填槽位：`customer_name`、`dispute_date`
- 可选槽位：`last_loan_date`、`loan_count`、`outstanding_amount`

`guide_loan_operation` — 引导用户在 APP 完成借款操作。先调用 query_account 获取 available_credit，再调用 get_agent_history API；历史中同一话术出现 2 次以上时改为 escalate_to_human
- 必填槽位：`customer_name`
- 可选槽位：`available_credit`

`escalate_to_human` — 转接人工客服。触发条件：同一问题重复解释 2 次以上无效、用户明确投诉、复杂账单争议
- 必填槽位：`customer_name`
- 可选槽位：`dispute_date`、`inquiry_amount`

`say_goodbye` — 礼貌告别。必须先调用 query_unresolved_issues API，确认 issue_count=0（无未解决诉求）才可执行告别，否则继续解决用户问题或转人工
- 必填槽位：`customer_name`
- 可选槽位：—

### 2.3 执行引擎注册的 CRM API

`calculate_repayment`

```
calculate_repayment(amount: int = None, months: int = None) -> dict
```
> 计算指定金额和期数的月还款额和总手续费。
>
> 在 calculate_repayment / explain_interest_rate 意图时调用。
> LLM 有时以字符串形式传入数值参数，此处强制转为整数以避免类型错误。

`get_agent_history`

```
get_agent_history() -> dict
```
> 返回对话历史中所有坐席发言的列表。
>
> 对话管理器在生成回复前调用此 API，
> 对照历史话术避免重复说完全相同的内容；
> 若历史中同一话术已出现 2 次以上，应改变表达或转人工。

`query_account`

```
query_account() -> dict
```
> 查询客户账户信息（额度、利率、账单、绑定银行等）。
>
> 动作解析器在 explain_credit_limit / explain_displayed_amount 意图时
> 必须先调用此 API 获取 available_credit，不得自行估算（防止数据错误）。
> 坐席在身份核实后需要报告绑定银行时也应调用此 API。

`query_customer_profile`

```
query_customer_profile() -> dict
```
> 查询客户背景信息：注册时间、授信天数、登录历史、电话接通记录、优惠券等。
>
> 在以下场景下调用：
> · 坐席需要说明客户注册时间（"您是我们安逸花XX年XX月份申请的优质用户"）
> · 坐席需要了解客户活跃度（登录频次、上次登录时间）
> · 坐席需要说明优惠券信息
> · 坐席需要了解累计提现笔数或授信天数以说明合作历史

`query_loan_records`

```
query_loan_records() -> dict
```
> 查询客户借款记录（用于 handle_loan_dispute 意图）。
>
> 提供历史借款笔数、最近借款日期、未还款金额、距离上次借款天数及借款还清日期，
> 帮助坐席核实用户争议的借款事实。

`query_unresolved_issues`

```
query_unresolved_issues() -> dict
```
> 返回最近对话中用户尚未得到回答的诉求列表。
>
> 对话管理器在执行 say_goodbye 意图前调用此 API，
> 仅当 issue_count=0（无未解决诉求）时才可礼貌告别，
> 否则应继续解决问题或转人工，不得直接告别。

`verify_customer`

```
verify_customer(name: str = None, phone_suffix: str = None) -> dict
```
> 核实客户身份：验证来电人提供的姓名和手机尾号与系统记录是否一致。
>
> 动作解析器在 verify_identity 意图时调用此 API，
> 通过对比用户提供的姓名和手机尾号来确认来电者是账户本人。
>
> 返回的 identity_confirmed 字段供对话管理器（LLM）决策：
> · identity_confirmed=True：可继续告知账户信息并推介借款
> · identity_confirmed=False：不应告知账户详情，应礼貌询问或终止通话
