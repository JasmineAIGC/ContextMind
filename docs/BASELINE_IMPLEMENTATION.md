## 概述

槽位模板方案（Slot Template Baseline）是一个**简单、独立的上下文优化基础版本**，作为与 ContextMind 复杂上下文工程框架进行对比实验的基线（baseline）。

### 核心特点

- ✅ **简单直接**：逻辑清晰，易于理解和实现
- ✅ **独立模块**：与 ContextMind 完全解耦，互不影响
- ✅ **无记忆库**：不依赖长期记忆，仅基于当前会话
- ✅ **槽位填充**：通过预定义槽位结构化表示上下文
- ✅ **对比基线**：作为 baseline 用于对比实验

---

## 背景与动机

### 为什么需要 baseline？

在评估 ContextMind 这样的复杂上下文工程框架时，需要一个**简单的基线方案**来进行对比，以便：

1. **量化改进效果**：通过对比了解复杂方案带来的实际提升
2. **理解核心价值**：明确哪些功能是关键的，哪些是锦上添花
3. **成本效益分析**：评估复杂度增加是否值得
4. **教学示例**：帮助理解上下文优化的基本原理

### 为什么选择槽位模板？

槽位模板是一个经典的、被广泛理解的方法：

- **概念简单**：预定义几个槽位，填充信息即可
- **实现快速**：无需复杂的检索、压缩等机制
- **资源占用低**：不需要向量数据库、嵌入模型等
- **效果可预测**：行为明确，便于分析

## 设计思路

### 核心思想

```
对话历史 → 提取关键信息 → 填充槽位 → 生成提示词 → 指导 LLM
```

### 槽位定义

定义三个核心槽位来表示上下文：

| 槽位名称 | 描述 | 示例 |
|---------|------|------|
| `user_intent` | 用户当前意图 | "用户意图：咨询" |
| `conversation_context` | 对话上下文摘要 | "已进行 3 轮对话。用户最近提到：..." |
| `key_info` | 关键信息（实体、偏好等） | "提到实体: 张三; 涉及数字: 100" |

### 工作流程

1. **历史回顾**：查看对话历史
2. **意图提取**：分析用户意图和关键信息
3. **槽位填充**：将提取的信息填入对应槽位
4. **模板渲染**：将槽位值填充到系统提示词模板
5. **生成回复**：使用填充后的提示词指导 LLM

## 实现架构

### 模块结构

```
baseline/
├── __init__.py              # 模块入口
├── engine.py                # SlotTemplateEngine - 核心引擎
├── intent_extractor.py      # IntentExtractor - 意图提取器
├── template_manager.py      # TemplateManager - 模板管理器
└── README.md                # 模块文档
```

### 核心组件

#### 1. SlotTemplateEngine（引擎）

**职责**：
- 整合各个组件
- 管理对话历史
- 提供统一的 API

**关键方法**：
```python
async def process(user_input, system_prompt_template=None)
    # 处理用户输入，返回槽位值和填充后的提示词

async def generate_prompt(user_input, system_prompt_template)
    # 生成完整的提示词

def add_message(role, content)
    # 添加消息到历史

def clear_history()
    # 清空历史
```

#### 2. IntentExtractor（意图提取器）

**职责**：
- 从对话历史中提取意图和关键信息
- 支持两种提取方式：规则提取和 LLM 提取

**提取方式**：

a) **规则提取**（默认）：
- 基于关键词匹配识别意图
- 使用正则表达式提取实体
- 统计最近对话轮数
- 优点：快速、无需 API 调用
- 缺点：准确度有限

b) **LLM 提取**（可选）：
- 调用 LLM 智能分析对话
- 生成结构化的槽位信息
- 优点：更准确、理解更深入
- 缺点：需要额外的 API 调用

#### 3. TemplateManager（模板管理器）

**职责**：
- 定义槽位模板
- 管理槽位值
- 填充模板字符串

**核心功能**：
```python
set_slot_value(slot_name, value)     # 设置槽位值
get_slot_value(slot_name)            # 获取槽位值
fill_template(template)              # 填充模板
```

## 与 ContextMind 的对比

### 功能对比表

| 功能 | 槽位模板 | ContextMind |
|------|---------|------------|
| **上下文来源** | 仅当前会话历史 | 会话历史 + 长期记忆 + 外部知识 |
| **记忆管理** | ❌ 无 | ✅ 完整的记忆库系统 |
| **语义检索** | ❌ 无 | ✅ 基于向量的语义检索 |
| **上下文压缩** | ❌ 无 | ✅ 智能压缩，减少 token |
| **上下文重排序** | ❌ 无 | ✅ 优化顺序，提升效果 |
| **知识提取** | ❌ 无 | ✅ 自动提取并存储知识 |
| **跨会话记忆** | ❌ 无 | ✅ 支持 |
| **实现复杂度** | ⭐ 简单 | ⭐⭐⭐⭐ 复杂 |
| **资源需求** | 低 | 中高（需要向量数据库等） |
| **适用场景** | 简单对话、baseline | 生产环境、复杂应用 |

### 架构对比

**槽位模板架构**：
```
用户输入 → IntentExtractor → TemplateManager → 提示词 → LLM
            ↑
         对话历史
```

**ContextMind 架构**：
```
用户输入 → InputPreprocessor
            ↓
         ContextRetriever ← MemoryBank (长期记忆)
            ↓                  ↓
         SessionManager (会话历史)
            ↓
         ContextCompressor
            ↓
         ContextReorderer
            ↓
         构建提示 → LLM → ResponseHandler
                              ↓
                         提取知识 → 更新记忆库
```

### 性能对比

**速度**：
- 槽位模板：~0.001s（规则提取）
- ContextMind：~0.0002-0.01s（取决于配置）

**准确性**：
- 槽位模板：基础级别，依赖简单规则
- ContextMind：高级，基于语义理解

**资源消耗**：
- 槽位模板：极低
- ContextMind：中等（需要向量计算）

## 使用指南

### 基本使用

```python
from baseline import SlotTemplateEngine
from prompts import BASELINE_SYSTEM_PROMPT

# 1. 初始化引擎
engine = SlotTemplateEngine(
    llm_client=None,         # None = 规则提取
    use_llm_extraction=False
)

# 2. 添加对话历史
engine.add_message("user", "我叫张三")
engine.add_message("assistant", "很高兴认识你，张三！")

# 3. 处理当前输入
result = await engine.process(
    user_input="你还记得我叫什么吗？",
    system_prompt_template=BASELINE_SYSTEM_PROMPT
)

# 4. 获取槽位值
print(result['slot_values'])
# {
#   "user_intent": "用户意图：咨询",
#   "conversation_context": "已进行 1 轮对话...",
#   "key_info": "提到实体: 张三"
# }

# 5. 获取填充后的提示词
prompt = result['filled_prompt']

# 6. 调用 LLM（用户自己的代码）
# response = await your_llm.chat(prompt)

# 7. 添加回复到历史
engine.add_message("assistant", response)
```

## 实验对比

### 实验场景

我们设计了 4 个测试场景来对比两种方案：

1. **简单问候场景**：测试基础对话能力
2. **自我介绍场景**：测试记忆用户信息的能力
3. **客服咨询场景**：测试业务对话能力
4. **多轮复杂对话**：测试综合信息整合能力

### 实验结果示例

**场景：自我介绍后询问**

对话历史：
```
用户: 我叫张三
助手: 很高兴认识你，张三！
用户: 我喜欢编程
助手: 编程是个很棒的爱好！
```

当前输入：`你还记得我叫什么吗？`

**槽位模板结果**：
```
槽位信息:
  user_intent: 用户意图：咨询
  conversation_context: 已进行 2 轮对话。用户最近提到：我喜欢编程...
  key_info: 提到实体: 张三
  
耗时: 0.0009s
```

**ContextMind 结果**：
```
上下文优化结果:
  上下文项数量: 4 (历史对话)
  是否压缩: False
  长期记忆: 0 条（首次对话，尚未提取）
  
耗时: 0.0002s
```

### 实验结论

1. **速度**：在简单场景下两者速度相近，ContextMind 可能更快（无需字符串处理）
2. **准确性**：ContextMind 在复杂场景下显著优于槽位模板
3. **记忆能力**：ContextMind 支持跨会话记忆，槽位模板不支持
4. **资源消耗**：槽位模板更轻量，ContextMind 需要更多资源

## 总结

### 槽位模板的价值

作为 baseline，槽位模板方案：

✅ **验证了基础可行性**：简单的槽位填充也能工作  
✅ **提供了对比基线**：帮助量化 ContextMind 的提升  
✅ **教学价值高**：易于理解上下文优化的基本原理  
✅ **适合快速原型**：无需复杂设置即可开始实验

### 选择建议

**选择槽位模板，如果**：
- 需要快速原型验证想法
- 场景简单，不需要长期记忆
- 资源受限，无法部署复杂系统
- 作为对比实验的 baseline

**选择 ContextMind，如果**：
- 需要生产级别的对话系统
- 需要长期记忆和跨会话连贯性
- 对话复杂，需要智能检索和优化
- 追求最佳的对话质量

### 未来改进方向

槽位模板可以进一步改进：

1. **槽位扩展**：增加更多槽位类型
2. **提取优化**：改进规则或增强 LLM 提取
3. **上下文压缩**：添加简单的压缩机制
4. **持久化**：添加简单的会话持久化

但即使有这些改进，槽位模板仍然是一个**简单的 baseline**，不应该变得过于复杂，否则就失去了作为 baseline 的意义。
