# DST预测质量改进

## 问题描述

根据用户报告："dst 预测出来 槽位-槽值 结果非常差，另外意图 几乎都错误。"

### 具体表现

从 `logs/temp.log` 分析：

**问题1：槽位提取质量差（0%准确率）**
```
期望状态: {'旅游景点-名称': '金鸡湖 景区'}
提取状态: {'intent': '咨询景点', '景区名称': '金鸡湖', '特点需求': '了解'}
匹配数: 0/1
```

- 缺少领域前缀（`景区名称` vs `旅游景点-名称`）
- 提取了无关信息（`特点需求`、`用户感受` 等）
- 槽位名称不规范

**问题2：意图推断错误（16.67%准确率）**
```
轮次意图: Inform -> Bye ✗
轮次意图: General -> Bye ✗
轮次意图: Request -> Bye ✗
```

所有轮次的意图都被推断为 "Bye"，只有最后一轮正确。

## 根本原因

### 1. Prompt过于宽松

原提示词：
```
**核心原则：完全开放式提取，不限制任何信息类型或领域。**
```

这导致LLM：
- 提取所有信息（包括情感、礼貌用语等）
- 使用自然语言命名（`景区名称` 而非 `旅游景点-名称`）
- 无结构化约束

### 2. 缺少领域引导

- 没有告诉LLM当前对话领域
- 没有要求使用领域前缀格式
- 没有说明哪些信息应该提取、哪些不应该提取

### 3. Intent字段污染

- LLM的intent预测作为槽位混入
- Intent推断从污染的槽位中进行，导致错误

## 解决方案

### Phase 1: RiSAWOZ专用Prompt ✅

**实现**: 在 `contextmind/modes/dst/prompt_manager.py`

#### 1.1 领域检测

```python
is_risawoz_domain = self.domain in ['医院', '天气', '旅游景点', '汽车', 
                                    '火车', '电影', '电脑', '电视剧', 
                                    '辅导班', '通用', '酒店', '飞机', '餐厅']
```

#### 1.2 结构化提示

如果是RiSAWOZ领域，使用专门的提示：

```
**重要：你正在为"{domain}"领域提取对话状态，请严格遵循以下规范。**

**核心原则：提取对话状态相关的槽位信息，使用标准格式。**

1. **槽位提取规范**：
   - 只提取与任务相关的槽位信息（名称、地点、时间、价格、特征等）
   - **槽位命名格式**：使用 "{domain}-槽位名" 格式
   - **不要提取**：用户的情感、礼貌用语（谢谢、再见等）、对话管理词汇
   - 只提取用户**提供**的信息，不要提取用户**询问**的内容
```

#### 1.3 明确示例

```
✓ {"旅游景点-区域": "苏州"}
✓ {"旅游景点-消费": "偏贵"}
✗ {"名称": "某地名"}（缺少领域前缀）
✗ {"谢谢": "谢谢"}（提取了无关信息）
```

### Phase 2: 输出格式强化 ✅

**实现**: 同样在 `prompt_manager.py`

```
**正确示例（{domain}领域）：**
✓ {"{domain}-名称": "某地名", "{domain}-区域": "某区域"}
✓ {}（如果没有提取到任何槽位信息）

**错误示例（不要这样）：**
❌ {"名称": "某地名"}（缺少领域前缀）
❌ {"谢谢": "谢谢", "再见": "再见"}（提取了无关信息）
❌ {"用户感受": "很期待"}（提取了情感信息）
```

## 技术细节

### Prompt变化对比

**旧版Prompt**:
- 开放式提取："不限制任何信息类型或领域"
- 自由命名：LLM自主决定槽位名称
- 包含情感：提取"情感态度"、"元信息"等

**新版Prompt（RiSAWOZ）**:
- 结构化提取："严格遵循以下规范"
- 标准格式：强制 `{domain}-槽位名`
- 任务聚焦：只提取状态相关信息

### 代码位置

- **文件**: `contextmind/modes/dst/prompt_manager.py`
- **方法**: `get_system_instruction()`
- **行数**: ~235-365

## 后续优化

## 总结

通过为RiSAWOZ任务提供专门的结构化prompt，我们：

1. ✅ 明确了槽位命名规范（领域前缀）
2. ✅ 限制了提取范围（只提取状态信息）
3. ✅ 提供了清晰的示例
4. ✅ 保持了对其他任务的兼容性

这应该能大幅提升DST预测质量。
