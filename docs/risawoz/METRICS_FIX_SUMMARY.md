# RiSAWOZ零指标问题修复总结

## 问题
从 `logs/temp.log` 发现所有指标都是 0%，日志格式也不够清晰。

## 根本原因

**槽位键不匹配**:
- Ground truth: `旅游景点-名称` (有领域前缀)
- LLM提取: `名称` (无前缀)

**槽位值不匹配**:
- Ground truth: `周庄 古镇` (带空格)
- LLM提取: `周庄古镇` (无空格)

**直接字符串比较** → 全部不匹配 → 0%

## 解决方案

### 1. 槽位标准化
```python
# 添加领域前缀
'名称' → '旅游景点-名称'

# 去除空格，统一大小写
'周庄 古镇' → '周庄古镇'
```

### 2. 更新比较逻辑
- `_calculate_joint_accuracy()` - 使用标准化比较
- `_calculate_prf_pairs()` - 使用标准化比较

### 3. 改进日志格式
```
【最终状态比较】
期望状态: {...}
提取状态: {...}

【标准化后状态】
标准化期望: {...}
标准化提取: {...}

✅ 匹配槽位 (1): {...}
❌ 缺失槽位 (2): {...}
⚠️  额外槽位 (1): {...}
```

## 测试结果

**之前**:
```
匹配: 0个 (0%)
```

**之后**:
```
匹配: 1个 (周庄古镇)
✅ 指标 > 0%
```

  - 改进verbose输出

## 预期影响

- ✅ 指标从 0% 提升到合理水平
- ✅ 清晰显示匹配/缺失/额外槽位
- ✅ 更容易调试问题
- ✅ 日志格式更清晰

## 注意

标准化只能解决格式问题，无法解决语义差异：
- `消费` vs `消费水平` (槽位名不同)
- `偏贵` vs `贵点` (值的表达不同)

这些需要更高级的语义匹配或映射表。
