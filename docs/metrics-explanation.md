## 对话状态跟踪 (DST) 指标

对话状态跟踪评测主要衡量模型在多轮对话中跟踪和更新槽位值的能力。

### 1. 槽位准确率 (Slot Accuracy)

**含义**：每个轮次中，所有槽位值都预测正确的比例

**计算公式**：
```
Slot Accuracy = 正确预测的槽位数 / 总槽位数
```

**说明**：
- 衡量模型对单个槽位值的预测准确性
- 每个轮次独立计算，然后取平均
- 关注细粒度的槽位级别性能

**示例**：
```
期望状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01", 房间数: "1"}
预测状态: {酒店名称: "希尔顿", 入住日期: "2024-01-02", 房间数: "1"}
槽位准确率: 2/3 = 66.67%  (酒店名称和房间数正确，入住日期错误)
```

---

### 2. 联合准确率-严格 (Joint Accuracy Strict)

**含义**：对话结束时，整个对话状态完全匹配的比例

**计算公式**：
```
Joint Accuracy Strict = 完全匹配的对话数 / 总对话数
```

**说明**：
- 最终状态必须完全一致（所有槽位名和值都要完全相同）
- 对话级别评测，要求最严格
- 与 TransferTOD 论文的 Joint Accuracy 定义一致

**示例**：
```
期望状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01"}
预测状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01"}
结果: ✅ 完全匹配

期望状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01"}
预测状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01", 房间数: "1"}
结果: ❌ 不匹配（有额外槽位）
```

---

### 3. 联合准确率-软匹配 (Joint Accuracy Soft)

**含义**：对话结束时，所有期望的槽位都存在的比例

**计算公式**：
```
Joint Accuracy Soft = 包含所有期望槽位的对话数 / 总对话数
```

**说明**：
- 允许预测结果中有额外的槽位，只要包含所有期望的槽位即可
- 比严格模式更宽松，适合评估槽位覆盖能力
- 可以容忍模型提取的冗余信息

**示例**：
```
期望状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01"}
预测状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01", 房间数: "1"}
结果: ✅ 软匹配成功（包含所有期望槽位，有额外槽位也可以）

期望状态: {酒店名称: "希尔顿", 入住日期: "2024-01-01"}
预测状态: {酒店名称: "希尔顿"}
结果: ❌ 软匹配失败（缺少入住日期）
```

---

### 4. 精确率 (Precision)

**含义**：模型预测的槽位-值对中，正确的比例

**计算公式**：
```
Precision = TP / (TP + FP)
```

**说明**：
- 衡量预测结果的准确性
- 值越高说明预测越可靠，误判越少
- 关注"预测为正例中有多少是真正例"

**应用场景**：
- 需要高精确率：避免错误信息影响用户体验
- 例如：酒店预订场景，错误的价格信息会造成严重后果

---

### 5. 召回率 (Recall)

**含义**：标准答案中的槽位-值对，被模型正确预测的比例

**计算公式**：
```
Recall = TP / (TP + FN)
```

**说明**：
- 衡量模型的覆盖能力
- 值越高说明遗漏越少
- 关注"真正例中有多少被预测出来"

**应用场景**：
- 需要高召回率：确保不遗漏关键信息
- 例如：医疗诊断场景，遗漏症状可能导致误诊

---

### 6. F1分数 (F1 Score)

**含义**：精确率和召回率的调和平均数

**计算公式**：
```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

**说明**：
- 综合衡量模型性能，平衡精确率和召回率
- 当精确率和召回率差异较大时，F1分数会偏低
- 是最常用的综合评价指标

**应用场景**：
- 需要平衡准确性和覆盖度的场景
- 大多数对话系统使用 F1 作为主要评价指标

## 意图识别 (Intent Recognition) 指标

意图识别评测衡量模型正确识别用户意图的能力。

### 1. 对话意图准确率 (Dialogue Intent Accuracy)

**含义**：对话级别的意图识别准确率

**计算公式**：
```
Dialogue Intent Accuracy = 意图完全正确的对话数 / 总对话数
```

**说明**：
- 衡量整个对话的意图是否被正确识别
- 对话级别的整体评测
- 适合评估对话意图的识别效果

---

### 2. 精确率 (Precision)

**含义**：模型预测为某个意图的样本中，真正属于该意图的比例

**计算公式**：
```
Precision = TP / (TP + FP)
```

**说明**：
- 衡量预测结果的准确性
- 值越高说明误判越少
- 关注预测的可靠性

---

### 3. 召回率 (Recall)

**含义**：真正属于某个意图的样本中，被模型正确识别的比例

**计算公式**：
```
Recall = TP / (TP + FN)
```

**说明**：
- 衡量模型的覆盖能力
- 值越高说明遗漏越少
- 关注识别的完整性

---

### 4. F1分数 (F1 Score)

**含义**：精确率和召回率的调和平均数

**计算公式**：
```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

**说明**：
- 综合衡量模型性能
- 平衡精确率和召回率

---

### 5. 宏平均 (Macro Average)

**含义**：对每个意图类别分别计算指标，再取平均值

**计算方法**：
```
Macro-Precision = (Precision₁ + Precision₂ + ... + Precisionₙ) / n
Macro-Recall = (Recall₁ + Recall₂ + ... + Recallₙ) / n
Macro-F1 = (F1₁ + F1₂ + ... + F1ₙ) / n
```

**特点**：
- 每个类别权重相同，不考虑样本数量
- 对低频意图类别更敏感

**适用场景**：
- 关注所有意图类别的整体表现
- 需要确保低频意图也被正确识别
- 类别不平衡时，想要平等对待每个类别

**示例**：
```
类别A (100个样本): Precision=90%, Recall=85%, F1=87.4%
类别B (10个样本):  Precision=60%, Recall=50%, F1=54.5%

宏平均:
Macro-Precision = (90% + 60%) / 2 = 75%
Macro-F1 = (87.4% + 54.5%) / 2 = 71.0%
```

---

### 6. 微平均 (Micro Average)

**含义**：将所有意图类别的 TP、FP、FN 汇总后再计算指标

**计算方法**：
```
Total_TP = TP₁ + TP₂ + ... + TPₙ
Total_FP = FP₁ + FP₂ + ... + FPₙ
Total_FN = FN₁ + FN₂ + ... + FNₙ

Micro-Precision = Total_TP / (Total_TP + Total_FP)
Micro-Recall = Total_TP / (Total_TP + Total_FN)
Micro-F1 = 2 × (Micro-Precision × Micro-Recall) / (Micro-Precision + Micro-Recall)
```

**特点**：
- 样本多的类别权重更大
- 反映整体样本的识别效果

**适用场景**：
- 关注整体样本的识别效果
- 高频意图更重要的场景
- 类别不平衡时，想要侧重多数类别

**示例**：
```
类别A (100个样本): TP=85, FP=10, FN=15
类别B (10个样本):  TP=5,  FP=3,  FN=5

微平均:
Total_TP = 85 + 5 = 90
Total_FP = 10 + 3 = 13
Total_FN = 15 + 5 = 20

Micro-Precision = 90 / (90 + 13) = 87.4%
Micro-Recall = 90 / (90 + 20) = 81.8%
Micro-F1 = 2 × (87.4% × 81.8%) / (87.4% + 81.8%) = 84.5%
```

---

### 7. 支持数 (Support)

**含义**：测试集中该意图类别的真实样本数量

**说明**：
- 用于了解每个意图类别的数据分布
- 帮助判断指标的可靠性
- 支持数越多，指标越可靠

## 术语解释

### TP (True Positive) - 真正例
- 模型预测为正例，实际也是正例
- 正确预测的样本

### FP (False Positive) - 假正例
- 模型预测为正例，实际是负例
- 误判的样本（Type I Error）

### FN (False Negative) - 假负例
- 模型预测为负例，实际是正例
- 遗漏的样本（Type II Error）

### TN (True Negative) - 真负例
- 模型预测为负例，实际也是负例
- 正确拒绝的样本

## 指标选择建议

### 选择精确率 (Precision)
- 误判代价高的场景
- 需要确保预测结果可靠
- 宁可遗漏，不要误判

### 选择召回率 (Recall)
- 遗漏代价高的场景
- 需要尽可能覆盖所有正例
- 宁可误判，不要遗漏

### 选择 F1 分数
- 需要平衡精确率和召回率
- 大多数场景的推荐指标
- 综合评价模型性能

### 选择宏平均 (Macro Average)
- 关注所有类别的平等表现
- 低频类别也很重要
- 类别不平衡时仍想平等对待

### 选择微平均 (Micro Average)
- 关注整体样本的识别效果
- 高频类别更重要
- 反映实际使用中的性能

## 常见问题分析

### 为什么微平均的 Precision、Recall、F1 总是相等？

在**单标签多分类**（每个对话只有一个意图）任务中，这是正常的数学现象，不是 Bug。

**原因**：设总样本数为 N，由于每个样本都有预测且只有一个真实标签：
- `ΣTP + ΣFP = N`（所有预测总数）
- `ΣTP + ΣFN = N`（所有真实标签总数）

因此：`Micro-Precision = Micro-Recall = Micro-F1 = ΣTP / N = Accuracy`

**结论**：在单标签意图分类中，微平均三指标必然相等，且等于准确率。关注**宏平均**指标可以发现各类别之间的性能差异。

---

### FnCTOD 为什么通常优于 DST？

| 维度 | DST 模式 | FnCTOD 模式 |
|------|---------|------------|
| 输入信息 | 对话历史（纯文本） | 对话历史 + 预定义 Schema |
| 槽位约束 | 无预定义约束 | 明确的槽位列表和类型约束 |
| 任务设定 | 开放式槽位提取 | 基于 Schema 的结构化填充 |
| 提示格式 | 自由文本 | 函数调用格式 |

FnCTOD 中预定义的 Schema 为 LLM 提供了更多结构化引导，减少了歧义，因此通常能获得更高的准确率（约高 10-15%）。

---

### 宏平均远低于微平均意味着什么？

**宏平均 << 微平均** → 说明**少数类别**（样本少的意图）性能较差。

**典型案例**：

```
意图类别    样本数    F1
预订酒店    1000     95%
查询天气     100     90%
询问时间      10     50%   ← 性能差

宏平均 F1 = (95 + 90 + 50) / 3 = 78%
微平均 F1 ≈ 93%               （高频类别主导）
```

**改进建议**：
- 收集更多少数类别的样本
- 使用类别加权损失函数
- 分析每个类别的详细指标，针对性优化
